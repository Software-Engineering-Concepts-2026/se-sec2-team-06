# User Stories — SynapseSync

User Stories ชุดนี้ derive จาก [`scenarios.md`](./scenarios.md) และใช้รูปแบบ As a / I want / So that พร้อม Acceptance Criteria ที่ตรวจสอบได้

> **Planning baseline:** ค่า Priority (MoSCoW) และ Estimate (S/M/L) ด้านล่างเป็นค่าที่ทีมบันทึกไว้สำหรับ Lab 03 และใช้เป็นข้อมูลอ้างอิงใน GitHub Issues หากมีการปรับระหว่าง Sprint Planning ต้องปรับ Issue และเอกสารให้ตรงกันด้วย

## US-01 — ถามคำถามเมื่อไม่เข้าใจ

**As a:** ปันปัน นักเรียนผู้เรียนรู้ด้วยตนเอง  
**I want:** ส่งคำถามเกี่ยวกับโจทย์หรือแนวคิดที่ไม่เข้าใจให้ผู้ช่วยได้ทันที  
**So that:** ฉันไม่ต้องเสียเวลาค้นหาคำอธิบายจากหลายแหล่ง

**Source scenario:** [S-01](./scenarios.md#s-01--แยกจุดที่ไม่เข้าใจก่อนอธิบาย)

### Acceptance Criteria

- [ ] ผู้เรียนที่เข้าสู่ระบบแล้วพิมพ์คำถามที่มีข้อความและกด **ส่ง** ระบบรับคำถามและแสดงสถานะ **กำลังประมวลผล**
- [ ] ถ้าช่องคำถามว่าง ระบบไม่ส่งคำขอและแจ้งให้ผู้เรียนกรอกคำถาม
- [ ] ถ้าบริการ AI ไม่พร้อม ระบบแจ้งข้อผิดพลาดและเก็บข้อความคำถามไว้ให้ผู้เรียนส่งใหม่ได้

**Priority:** Must  
**Estimate:** M

## US-02 — ระบุ Learning Gap ก่อนอธิบาย

**As a:** ปันปัน นักเรียนผู้เรียนรู้ด้วยตนเอง  
**I want:** ให้ผู้ช่วยถามกลับเมื่อคำถามของฉันยังมีบริบทไม่พอ  
**So that:** คำอธิบายที่ได้รับตรงกับปัญหาจริงของฉัน

**Source scenario:** [S-01](./scenarios.md#s-01--แยกจุดที่ไม่เข้าใจก่อนอธิบาย)

### Acceptance Criteria

- [ ] ถ้าคำถามกำกวมหรือข้อมูลไม่พอ ระบบถามคำถามเพิ่มเติมอย่างน้อย 1 ข้อก่อนอธิบาย
- [ ] หลังผู้เรียนตอบคำถามเพิ่มเติม ระบบใช้ข้อมูลนั้นประกอบคำอธิบายที่แสดง
- [ ] ถ้าผู้เรียนไม่ตอบจนหมดเวลา ระบบเก็บคำถามไว้และแสดงวิธีกลับมาทำต่อ

**Priority:** Must  
**Estimate:** M

## US-03 — สร้างแบบฝึกหัดที่สัมพันธ์กับหัวข้อ

**As a:** ปันปัน นักเรียนผู้เรียนรู้ด้วยตนเอง  
**I want:** ขอแบบฝึกหัดที่ใช้แนวคิดเดียวกับหัวข้อที่เพิ่งเรียน  
**So that:** ฉันตรวจสอบได้ว่าเข้าใจแนวคิดจริงก่อนสอบ

**Source scenario:** [S-02](./scenarios.md#s-02--ฝึกโจทย์และบันทึกความเข้าใจ)

### Acceptance Criteria

- [ ] เมื่อผู้เรียนเลือกหัวข้อและขอแบบฝึกหัด 2 ข้อ ระบบแสดงโจทย์ครบ 2 ข้อที่ตรงกับหัวข้อนั้น
- [ ] แต่ละโจทย์มีคำตอบหรือเกณฑ์ตรวจสอบที่ผู้เรียนใช้เช็กได้อย่างชัดเจน
- [ ] ถ้าระบบสร้างโจทย์ไม่สำเร็จ ระบบแจ้งข้อผิดพลาดและมีทางเลือกให้ลองใหม่ โดยไม่แสดงโจทย์ว่าง

**Priority:** Must  
**Estimate:** M

## US-04 — บันทึกผลการฝึก

**As a:** ปันปัน นักเรียนผู้เรียนรู้ด้วยตนเอง  
**I want:** ให้ระบบบันทึกหัวข้อ วันที่ และผลการฝึกหลังตรวจคำตอบ  
**So that:** ฉันติดตามความเข้าใจโดยไม่ต้องจดจำเอง

**Source scenario:** [S-02](./scenarios.md#s-02--ฝึกโจทย์และบันทึกความเข้าใจ)

### Acceptance Criteria

- [ ] หลังผู้เรียนส่งคำตอบครบและระบบตรวจเสร็จ ระบบบันทึกหัวข้อ วันที่ เวลา และผลการฝึก
- [ ] เมื่อผู้เรียนเปิดประวัติและเลือกหัวข้อเดิม ระบบแสดงผลการฝึกครั้งล่าสุดของหัวข้อนั้นถูกต้อง
- [ ] ถ้าผู้เรียนออกจากหน้าก่อนส่งคำตอบครบ ระบบไม่บันทึกรายการนั้นเป็นผลสำเร็จ

**Priority:** Must  
**Estimate:** S

## US-05 — ดูหัวข้อที่นักเรียนติดขัด

**As a:** ครูสมชาย Teacher Mentor  
**I want:** เห็นภาพรวมหัวข้อที่นักเรียนในกลุ่มติดขัดและสถานะการฝึก  
**So that:** ฉันจัดสรรเวลาสอนเสริมได้ตรงจุด

**Source scenario:** [S-04](./scenarios.md#s-04--ครูค้นหาหัวข้อที่นักเรียนติดขัด)

### Acceptance Criteria

- [ ] เมื่อครูที่มีสิทธิ์เปิด Dashboard ระบบแสดงหัวข้อที่ผู้เรียนในกลุ่มติดขัดและสถานะการฝึกของแต่ละหัวข้อ
- [ ] เมื่อครูเลือกหัวข้อหรือช่วงเวลาแล้วกดยืนยัน ระบบอัปเดตสรุปให้ตรงกับตัวกรองนั้น
- [ ] ถ้ากลุ่มเรียนยังไม่มีข้อมูล ระบบแสดงข้อความว่าไม่มีข้อมูลพร้อมคำแนะนำ และไม่แสดงข้อมูลปลอม

**Priority:** Should  
**Estimate:** L

## US-06 — ตรวจความสดใหม่และสิทธิ์ของข้อมูล

**As a:** ครูสมชาย Teacher Mentor  
**I want:** เห็น timestamp ของข้อมูลล่าสุดและถูกจำกัดเฉพาะกลุ่มที่ฉันรับผิดชอบ  
**So that:** ฉันใช้ข้อมูลที่เหมาะสมและไม่เปิดเผยข้อมูลผู้เรียนเกินสิทธิ์

**Source scenario:** [S-05](./scenarios.md#s-05--ครูตรวจความสดใหม่และสิทธิ์ข้อมูล)

### Acceptance Criteria

- [ ] หลัง sync สำเร็จ เมื่อครูเปิด Dashboard ระบบแสดงวันและเวลาที่ข้อมูลอัปเดตล่าสุด
- [ ] ถ้าครูไม่มีสิทธิ์ในกลุ่มที่ขอดู ระบบตอบกลับ HTTP 401/403 และไม่แสดงรายละเอียดของข้อมูล
- [ ] ถ้า sync ครั้งล่าสุดล้มเหลว ระบบแสดงเวลา sync ครั้งก่อนพร้อมแจ้งว่าข้อมูลอาจไม่ใช่ข้อมูลปัจจุบัน

**Priority:** Should  
**Estimate:** M

## US-07 — จัดการงานและกำหนดส่ง

**As a:** พี่เอิร์ธ Adult Learner  
**I want:** บันทึกงานพร้อมวิชา วัน–เวลา deadline และระดับความเร่งด่วน
**So that:** ฉันรู้ว่างานไหนต้องทำก่อนและวางแผนเวลาได้

**Source scenario:** [S-07](./scenarios.md#s-07--จัดการงานและกำหนดส่ง)

### Acceptance Criteria

- [ ] เมื่อผู้เรียนกรอกชื่องาน วิชา วันที่ และเวลา deadline แล้วกดบันทึก ระบบเพิ่มงานนั้นในรายการ
- [ ] รายการงานที่เพิ่มต้องแสดงชื่อ วิชา วัน–เวลา deadline และเรียงตามวันส่งเพื่อให้เห็นงานที่ใกล้ถึงกำหนดก่อน
- [ ] เมื่อผู้เรียนเลือกระดับความเร่งด่วน `ด่วน`, `ปานกลาง` หรือ `ไม่ด่วน` ระบบแสดงป้ายระดับนั้นบนงานที่บันทึกไว้
- [ ] เมื่อผู้เรียนเลือกตัวกรอง `ทั้งหมด`, `ยังไม่เสร็จ` หรือ `เสร็จแล้ว` ระบบแสดงเฉพาะงานที่ตรงกับตัวกรอง และแสดง empty state เมื่อไม่มีรายการ
- [ ] เมื่อผู้เรียนกดทำเครื่องหมายเสร็จหรือลบงาน ระบบเปลี่ยนเฉพาะงานที่เลือกและอัปเดตรายการทันที

**Priority:** Could  
**Estimate:** M

## US-08 — ดูภาพรวมความก้าวหน้า

**As a:** พี่เอิร์ธ Adult Learner  
**I want:** เห็นสรุปจำนวนหัวข้อ ผลล่าสุด และเวลาที่ฝึก  
**So that:** ฉันรู้ว่าควรทบทวนหัวข้อใดต่อและมีกำลังใจเรียนต่อ

**Source scenario:** [S-08](./scenarios.md#s-08--ผู้เรียนเปิด-progress-โดยยังไม่มีประวัติ)

### Acceptance Criteria

- [ ] ถ้าผู้เรียนมีประวัติการฝึก เมื่อเปิดหน้า Progress ระบบแสดงจำนวนหัวข้อ ผลล่าสุด และวัน–เวลาของข้อมูล
- [ ] ถ้าผู้เรียนยังไม่มีประวัติ ระบบแสดงข้อความว่าไม่มีข้อมูลพร้อมคำแนะนำให้เริ่มทำแบบฝึกหัด
- [ ] ถ้าผลการฝึกได้คะแนน 0 ระบบแสดงคะแนน 0 แยกจากกรณีที่ยังไม่มีข้อมูล

**Priority:** Should  
**Estimate:** M

## US-09 — จัดเก็บและเปิดดูเอกสารการเรียน

**As a:** พี่เอิร์ธ Adult Learner  
**I want:** อัปโหลด จัดหมวด และเปิดดูเอกสารการเรียนของฉัน
**So that:** ฉันกลับมาเปิดทบทวนเนื้อหาที่ต้องการได้จากที่เดียว

**Source scenario:** [S-09](./scenarios.md#s-09--จัดเก็บและเปิดดูเอกสารการเรียน)

### Acceptance Criteria

- [ ] เมื่อผู้เรียนเลือกไฟล์ที่รองรับและเลือกหมวดวิชาแล้ว ระบบเพิ่มการ์ดเอกสารที่แสดงชื่อไฟล์ ประเภท และหมวดวิชา
- [ ] เมื่อผู้เรียนเลือกตัวกรองหมวดวิชา ระบบแสดงเฉพาะเอกสารในหมวดนั้น และคงตัวกรอง `ทั้งหมด` ไว้สำหรับดูทุกรายการ
- [ ] เมื่อผู้เรียนกดการ์ดเอกสาร ระบบเปิดหน้า Document Viewer พร้อมแสดงข้อมูลของไฟล์และหมวดวิชาเดิม
- [ ] เมื่อผู้เรียนกดลบและยืนยัน ระบบลบเฉพาะเอกสารที่เลือกออกจากรายการ โดยไม่กระทบเอกสารอื่น
- [ ] เมื่อยังไม่มีเอกสารหรือไม่มีเอกสารตรงกับตัวกรอง ระบบแสดง empty state และไม่สร้างรายการเอกสารปลอม

**Priority:** Could  
**Estimate:** M

## US-10 — วางแผนสอนเสริมจากหลักฐาน

**As a:** ครูสมชาย Teacher Mentor  
**I want:** เปรียบเทียบแนวโน้มผลการฝึกของหัวข้อที่นักเรียนติดขัด  
**So that:** ฉันออกแบบกิจกรรมช่วยเหลือโดยใช้หลักฐานแทนการคาดเดา

**Source scenario:** [S-06](./scenarios.md#s-06--ครูวางแผนสอนเสริมจากหลักฐาน)

### Acceptance Criteria

- [ ] เมื่อครูที่มีสิทธิ์เลือกหัวข้อและช่วงเวลา ระบบแสดงแนวโน้มผลการฝึกของกลุ่มนั้น
- [ ] ถ้าข้อมูลการฝึกยังไม่เพียงพอ ระบบแจ้งข้อจำกัดและไม่สรุปว่าผู้เรียนเข้าใจแล้ว
- [ ] เมื่อครูเลือกหัวข้อที่ผู้เรียนตอบผิดซ้ำ ระบบแสดงหลักฐานที่ได้รับอนุญาต เช่น คำตอบผิดหรือคะแนนต่ำ เพื่อใช้วางแผนสอนเสริม

**Priority:** Should  
**Estimate:** L

## Quality Bar Check

| คำถาม | ผลตรวจร่างนี้ |
|---|---|
| Independent | Stories แยกเป็น flow ถาม, ฝึก, บันทึก, Dashboard, Deadline Planner และ Document Library ได้ |
| Valuable | ทุก Story ระบุประโยชน์ที่เชื่อมกับ Persona และ Scenario |
| Estimable | ทุก Story มี Estimate ระดับ S/M/L เป็น draft |
| Small | Story ที่ Large ถูกแยกจาก flow หลัก และระบุ Estimate L เพื่อวางแผนต่อ |
| Testable | ทุก Story มี Acceptance Criteria แบบ Given/When/Then หรือ checklist |

> US-07 ถึง US-09 เป็น Could/Should ที่ทีมตั้งใจเก็บไว้เป็นลำดับถัดไป เพื่อป้องกัน feature creep โดยยังคงอยู่ในชุด User Stories ของ Lab 03 และต้องใช้ Priority/Estimate เดียวกับ Issue ที่เชื่อมโยง
