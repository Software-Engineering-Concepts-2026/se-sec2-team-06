# User Stories — SynapseSync

User Stories ชุดนี้ derive จาก [`scenarios.md`](./scenarios.md) และใช้รูปแบบ As a / I want / So that พร้อม Acceptance Criteria ที่ตรวจสอบได้

> **หมายเหตุ:** Priority และ Estimate เป็น draft ที่ derive จาก MoSCoW และ INVEST note ของงานเดิม ทีมต้องยืนยันอีกครั้งใน Sprint Planning ก่อนสร้าง GitHub Issue จริง

## US-01 — ถามคำถามเมื่อไม่เข้าใจ

**As a:** ปันปัน นักเรียนผู้เรียนรู้ด้วยตนเอง  
**I want:** ส่งคำถามเกี่ยวกับโจทย์หรือแนวคิดที่ไม่เข้าใจให้ผู้ช่วยได้ทันที  
**So that:** ฉันไม่ต้องเสียเวลาค้นหาคำอธิบายจากหลายแหล่ง

**Source scenario:** [S-01](./scenarios.md#s-01--แยกจุดที่ไม่เข้าใจก่อนอธิบาย)

**Acceptance Criteria**

- [ ] **Given** ผู้เรียนเข้าสู่ระบบแล้ว **When** ส่งคำถามที่มีข้อความ **Then** ระบบรับคำถามและแสดงสถานะกำลังประมวลผล
- [ ] **Given** ช่องคำถามว่าง **When** ผู้เรียนกดส่ง **Then** ระบบไม่ส่งคำขอและแจ้งให้กรอกคำถาม
- [ ] **Given** บริการ AI ไม่พร้อม **When** ผู้เรียนส่งคำถาม **Then** ระบบแจ้งปัญหาโดยไม่ทำให้ข้อความสูญหาย

**Priority:** Must  
**Estimate:** M

## US-02 — ระบุ Learning Gap ก่อนอธิบาย

**As a:** ปันปัน นักเรียนผู้เรียนรู้ด้วยตนเอง  
**I want:** ให้ผู้ช่วยถามกลับเมื่อคำถามของฉันยังมีบริบทไม่พอ  
**So that:** คำอธิบายที่ได้รับตรงกับปัญหาจริงของฉัน

**Source scenario:** [S-01](./scenarios.md#s-01--แยกจุดที่ไม่เข้าใจก่อนอธิบาย)

**Acceptance Criteria**

- [ ] **Given** คำถามมีความกำกวม **When** ระบบมีข้อมูลไม่พอ **Then** ระบบถามคำถามชี้แจงอย่างน้อย 1 ข้อก่อนอธิบาย
- [ ] **Given** ผู้เรียนตอบคำถามชี้แจงแล้ว **When** ระบบสร้างคำอธิบาย **Then** คำอธิบายอ้างอิงบริบทที่ผู้เรียนเพิ่มเข้ามา
- [ ] **Given** ผู้เรียนไม่ตอบคำถามชี้แจง **When** session หมดเวลา **Then** ระบบเก็บคำถามไว้และแจ้งให้กลับมาต่อได้

**Priority:** Must  
**Estimate:** M

## US-03 — สร้างแบบฝึกหัดที่สัมพันธ์กับหัวข้อ

**As a:** ปันปัน นักเรียนผู้เรียนรู้ด้วยตนเอง  
**I want:** ขอแบบฝึกหัดที่ใช้แนวคิดเดียวกับหัวข้อที่เพิ่งเรียน  
**So that:** ฉันตรวจสอบได้ว่าเข้าใจแนวคิดจริงก่อนสอบ

**Source scenario:** [S-02](./scenarios.md#s-02--ฝึกโจทย์และบันทึกความเข้าใจ)

**Acceptance Criteria**

- [ ] **Given** ผู้เรียนเลือกหัวข้อแล้ว **When** ขอแบบฝึกหัด 2 ข้อ **Then** ระบบแสดงโจทย์ 2 ข้อที่สัมพันธ์กับหัวข้อนั้น
- [ ] **Given** โจทย์ถูกสร้างแล้ว **When** ผู้เรียนเปิดโจทย์ **Then** ระบบแสดงคำตอบหรือเกณฑ์ตรวจสอบที่ชัดเจน
- [ ] **Given** ระบบสร้างโจทย์ไม่ได้ **When** provider แจ้งข้อผิดพลาด **Then** ระบบแจ้งปัญหาและให้ลองใหม่โดยไม่สร้างโจทย์ว่าง

**Priority:** Must  
**Estimate:** M

## US-04 — บันทึกผลการฝึก

**As a:** ปันปัน นักเรียนผู้เรียนรู้ด้วยตนเอง  
**I want:** ให้ระบบบันทึกหัวข้อ วันที่ และผลการฝึกหลังตรวจคำตอบ  
**So that:** ฉันติดตามความเข้าใจโดยไม่ต้องจดจำเอง

**Source scenario:** [S-02](./scenarios.md#s-02--ฝึกโจทย์และบันทึกความเข้าใจ)

**Acceptance Criteria**

- [ ] **Given** ผู้เรียนส่งคำตอบครบแล้ว **When** ระบบตรวจผลเสร็จ **Then** ระบบบันทึกหัวข้อ เวลา และผลการฝึก
- [ ] **Given** ผู้เรียนเปิดประวัติ **When** เลือกหัวข้อเดิม **Then** ระบบแสดงผลการฝึกครั้งล่าสุดได้ถูกต้อง
- [ ] **Given** ผู้เรียนออกจากหน้าก่อนส่งคำตอบ **When** กลับมาอีกครั้ง **Then** รายการยังไม่ถูกบันทึกเป็นผลสำเร็จ

**Priority:** Must  
**Estimate:** S

## US-05 — ดูหัวข้อที่นักเรียนติดขัด

**As a:** ครูสมชาย Teacher Mentor  
**I want:** เห็นภาพรวมหัวข้อที่นักเรียนในกลุ่มติดขัดและสถานะการฝึก  
**So that:** ฉันจัดสรรเวลาสอนเสริมได้ตรงจุด

**Source scenario:** [S-04](./scenarios.md#s-04--ครูค้นหาหัวข้อที่นักเรียนติดขัด)

**Acceptance Criteria**

- [ ] **Given** ครูมีสิทธิ์ดูแลกลุ่มเรียน **When** เปิด Dashboard **Then** ระบบแสดงหัวข้อที่มีการติดขัดและสถานะการฝึกของกลุ่มนั้น
- [ ] **Given** ครูกรองหัวข้อและช่วงเวลา **When** ยืนยันตัวกรอง **Then** ระบบอัปเดตสรุปตามเงื่อนไขที่เลือก
- [ ] **Given** กลุ่มเรียนยังไม่มีข้อมูล **When** เปิด Dashboard **Then** ระบบแสดง empty state พร้อมคำแนะนำ ไม่แสดงข้อมูลปลอม

**Priority:** Should  
**Estimate:** L

## US-06 — ตรวจความสดใหม่และสิทธิ์ของข้อมูล

**As a:** ครูสมชาย Teacher Mentor  
**I want:** เห็น timestamp ของข้อมูลล่าสุดและถูกจำกัดเฉพาะกลุ่มที่ฉันรับผิดชอบ  
**So that:** ฉันใช้ข้อมูลที่เหมาะสมและไม่เปิดเผยข้อมูลผู้เรียนเกินสิทธิ์

**Source scenario:** [S-05](./scenarios.md#s-05--ครูตรวจความสดใหม่และสิทธิ์ข้อมูล)

**Acceptance Criteria**

- [ ] **Given** ระบบ sync สำเร็จ **When** ครูเปิด Dashboard **Then** ระบบแสดงเวลาที่ข้อมูลอัปเดตล่าสุด
- [ ] **Given** ครูไม่มีสิทธิ์ในกลุ่มเรียน **When** ขอเปิดข้อมูล **Then** ระบบปฏิเสธด้วย HTTP 401/403 และไม่เปิดเผยรายละเอียด
- [ ] **Given** sync ครั้งล่าสุดล้มเหลว **When** ครูเปิด Dashboard **Then** ระบบแสดง timestamp เดิมพร้อมข้อความว่าไม่ใช่ข้อมูล real-time

**Priority:** Should  
**Estimate:** M

## US-07 — รับ Reminder เพื่อกลับมาทบทวน

**As a:** พี่เอิร์ธ Adult Learner  
**I want:** ตั้งเวลาและรับการเตือนหัวข้อที่ยังไม่ได้ทบทวน  
**So that:** ฉันเรียนต่อเนื่องได้แม้ตารางงานไม่แน่นอน

**Source scenario:** [S-07](./scenarios.md#s-07--ผู้เรียนวัยทำงานกลับมาเรียนจาก-reminder)

**Acceptance Criteria**

- [ ] **Given** ผู้เรียนเปิดการแจ้งเตือนและตั้งเวลาแล้ว **When** ถึงเวลาที่กำหนด **Then** ระบบสร้าง Reminder ที่อ้างอิงหัวข้อค้าง
- [ ] **Given** ผู้เรียนปิดการแจ้งเตือน **When** ถึงกำหนดเดิม **Then** ระบบไม่ส่ง Reminder
- [ ] **Given** ผู้เรียนกด Reminder **When** เปิดลิงก์ **Then** ระบบพากลับไปยังหัวข้อหรือจุดที่ค้างไว้

**Priority:** Could  
**Estimate:** M

## US-08 — ดูภาพรวมความก้าวหน้า

**As a:** พี่เอิร์ธ Adult Learner  
**I want:** เห็นสรุปจำนวนหัวข้อ ผลล่าสุด และเวลาที่ฝึก  
**So that:** ฉันรู้ว่าควรทบทวนหัวข้อใดต่อและมีกำลังใจเรียนต่อ

**Source scenario:** [S-08](./scenarios.md#s-08--ผู้เรียนเปิด-progress-โดยยังไม่มีประวัติ)

**Acceptance Criteria**

- [ ] **Given** ผู้เรียนมีประวัติการฝึก **When** เปิดหน้า Progress **Then** ระบบแสดงจำนวนหัวข้อ ผลล่าสุด และช่วงเวลาของข้อมูล
- [ ] **Given** ผู้เรียนยังไม่มีประวัติ **When** เปิดหน้า Progress **Then** ระบบแสดง empty state และคำแนะนำเริ่มต้น
- [ ] **Given** ผู้เรียนมีผลคะแนนศูนย์ **When** เปิดหน้า Progress **Then** ระบบแยกผลคะแนนศูนย์ออกจากสถานะยังไม่มีข้อมูล

**Priority:** Should  
**Estimate:** M

## US-09 — ทำแบบฝึกหัดต่อหลังถูกขัดจังหวะ

**As a:** พี่เอิร์ธ Adult Learner  
**I want:** กลับไปทำแบบฝึกหัดที่ยังไม่เสร็จต่อจากจุดเดิม  
**So that:** ฉันไม่ต้องเริ่มใหม่ทุกครั้งที่ตารางงานขัดจังหวะ

**Source scenario:** [S-09](./scenarios.md#s-09--ผู้เรียนทำต่อหลังถูกขัดจังหวะ)

**Acceptance Criteria**

- [ ] **Given** ผู้เรียนออกจากหน้าก่อนส่งคำตอบ **When** กลับมาเปิดรายการเดิม **Then** ระบบแสดงสถานะค้างและข้อมูลที่บันทึกล่าสุด
- [ ] **Given** ผู้เรียนส่งคำตอบครบแล้ว **When** ระบบตรวจผล **Then** ระบบบันทึกผลจริงเพียงครั้งเดียว
- [ ] **Given** ผู้เรียนเปิดรายการเดิมหลายครั้ง **When** ยังไม่ส่งคำตอบ **Then** ระบบไม่สร้างผลสำเร็จซ้ำ

**Priority:** Could  
**Estimate:** M

## US-10 — วางแผนสอนเสริมจากหลักฐาน

**As a:** ครูสมชาย Teacher Mentor  
**I want:** เปรียบเทียบแนวโน้มผลการฝึกของหัวข้อที่นักเรียนติดขัด  
**So that:** ฉันออกแบบกิจกรรมช่วยเหลือโดยใช้หลักฐานแทนการคาดเดา

**Source scenario:** [S-06](./scenarios.md#s-06--ครูวางแผนสอนเสริมจากหลักฐาน)

**Acceptance Criteria**

- [ ] **Given** ครูมีสิทธิ์ดูข้อมูลกลุ่ม **When** เลือกหัวข้อและช่วงเวลา **Then** ระบบแสดงแนวโน้มผลการฝึกที่เกี่ยวข้อง
- [ ] **Given** ผลการฝึกยังมีข้อมูลไม่พอ **When** ครูเปิดสรุป **Then** ระบบระบุข้อจำกัดของข้อมูลและไม่สรุปว่าเข้าใจแล้ว
- [ ] **Given** ครูเลือกหัวข้อที่ผิดซ้ำ **When** ดูรายละเอียดที่ได้รับอนุญาต **Then** ระบบแสดงหลักฐานที่ใช้ประกอบการวางแผน

**Priority:** Should  
**Estimate:** L

## Quality Bar Check

| คำถาม | ผลตรวจร่างนี้ |
|---|---|
| Independent | Stories แยกเป็น flow ถาม, ฝึก, บันทึก, Dashboard และ Reminder ได้ |
| Valuable | ทุก Story ระบุประโยชน์ที่เชื่อมกับ Persona และ Scenario |
| Estimable | ทุก Story มี Estimate ระดับ S/M/L เป็น draft |
| Small | Story ที่ Large ถูกแยกจาก flow หลัก และระบุ Estimate L เพื่อวางแผนต่อ |
| Testable | ทุก Story มี Acceptance Criteria แบบ Given/When/Then หรือ checklist |

> US-07 ถึง US-09 เป็น Could/Should draft ที่ต้องผ่าน MoSCoW และ team review ก่อนนำเข้า Sprint เพื่อป้องกัน feature creep
