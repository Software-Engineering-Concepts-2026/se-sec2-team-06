## S-01 — แยกจุดที่ไม่เข้าใจก่อนอธิบาย

**Persona:** ปันปัน — Student Learner  
**Objective:** ระบุให้ได้ว่าปันปันติดที่นิยาม สูตร หรือการประยุกต์ใช้ก่อนรับคำอธิบาย

**Narrative:** ปันปันกำลังทบทวนเรื่องโมเมนตัมและการชนก่อนสอบในอีกสามวัน เธอทำโจทย์การชนแบบไม่ยืดหยุ่นไม่ได้และไม่เข้าใจว่าทำไมพลังงานจลน์จึงไม่คงที่ เธอเปิด SynapseSync แล้วพิมพ์คำถามที่สงสัย ระบบตรวจว่าคำถามมีข้อมูลไม่พอ จึงถามกลับอย่างสุภาพว่าปันปันติดที่นิยาม สูตร หรือความแตกต่างระหว่างกฎอนุรักษ์ เมื่อเธอเลือกประเด็นที่สงสัย ระบบจึงอธิบายทีละขั้นและยกตัวอย่างที่ใกล้กับโจทย์เดิม

**Action sequence:** ปันปันเข้าสู่ระบบ → ส่งคำถาม → ระบบตรวจความกำกวม → ระบบถามคำถามชี้แจง → ปันปันให้บริบทเพิ่ม → ระบบแสดงคำอธิบายแบบเป็นขั้นตอน

**Problem/edge case:** หากช่องคำถามว่างหรือสั้นเกินไป ระบบต้องไม่เรียก AI และต้องบอกว่าต้องเติมข้อมูลอะไร

**Expected outcome:** ปันปันระบุ learning gap ของตนเองได้และบอกได้ว่าควรเริ่มทบทวนแนวคิดใด

## S-02 — ฝึกโจทย์และบันทึกความเข้าใจ

**Persona:** ปันปัน — Student Learner  
**Objective:** เปลี่ยนคำอธิบายให้เป็นการฝึกที่ตรวจสอบได้

**Narrative:** หลังอ่านคำอธิบาย ปันปันกดยืนยันว่าเข้าใจแนวคิดเรื่องการชนแล้วและขอแบบฝึกหัดที่ใช้หลักการเดียวกัน ระบบสร้างโจทย์ 2 ข้อพร้อมเกณฑ์ตรวจ ปันปันส่งคำตอบทีละข้อและได้รับผลย้อนกลับ เมื่อทำถูกทั้งสองข้อ ระบบบันทึกหัวข้อ วันที่ และผลการฝึกไว้ในประวัติ เพื่อให้เธอกลับมาดูได้ก่อนสอบ

**Action sequence:** ปันปันยืนยันความเข้าใจ → ขอแบบฝึกหัด → ระบบสร้างโจทย์ → ปันปันส่งคำตอบ → ระบบตรวจและอธิบายผล → ระบบบันทึกความก้าวหน้า

**Problem/edge case:** หากผู้เรียนออกจากหน้าระหว่างทำข้อที่สอง ระบบต้องไม่บันทึกผลที่ยังตรวจไม่เสร็จเป็นว่าสำเร็จแล้ว

**Expected outcome:** ปันปันมีหลักฐานการฝึกและเห็นหัวข้อที่ควรกลับไปทบทวนจากประวัติของตนเอง

## S-03 — ผู้ช่วย AI ไม่พร้อมใช้งาน

**Persona:** ปันปัน — Student Learner  
**Objective:** ให้ผู้เรียนได้รับ feedback ที่ชัดเจนเมื่อบริการภายนอกล้มเหลว

**Narrative:** ในช่วงก่อนสอบ ปันปันส่งคำถามใหม่แต่ผู้ให้บริการ AI ตอบช้าเกินกำหนด ระบบตรวจพบ timeout จึงไม่แสดงคำตอบที่อาจไม่สมบูรณ์และไม่ลบข้อความที่เธอพิมพ์ ระบบแสดงข้อความว่าบริการกำลังไม่พร้อม พร้อมให้ลองใหม่ภายหลัง ปันปันกลับมาเปิดคำถามเดิมหลังจากระบบกลับมาใช้งานได้และส่งซ้ำโดยไม่ต้องพิมพ์ใหม่

**Action sequence:** ปันปันส่งคำถาม → ระบบรอจนถึง timeout → ระบบบันทึกข้อความไว้ชั่วคราว → แสดงข้อความผิดพลาดที่เข้าใจได้ → ปันปันกดลองใหม่เมื่อ provider พร้อม

**Problem/edge case:** ระบบห้ามแสดงคำตอบที่ไม่มั่นใจเป็นข้อเท็จจริง และต้องไม่ทำให้หน้าจอค้าง

**Expected outcome:** ปันปันรู้ว่าต้องทำอะไรต่อและไม่สูญเสียบริบทของคำถาม

## S-04 — ครูค้นหาหัวข้อที่นักเรียนติดขัด

**Persona:** ครูสมชาย — Teacher Mentor  
**Objective:** ช่วยให้ครูเห็นภาพรวมโดยไม่ต้องเปิดประวัติทีละคน

**Narrative:** ก่อนวางแผนสอนเสริม ครูสมชายเปิด Dashboard ของกลุ่มเรียน เขาเห็นว่าหัวข้อการชนแบบไม่ยืดหยุ่นมีนักเรียนหลายคนถามซ้ำและมีผลการฝึกต่ำกว่าหัวข้ออื่น ครูกรองข้อมูลตามหัวข้อและช่วงเวลา แล้วเปิดดูเฉพาะข้อมูลสรุปที่จำเป็นต่อการวางแผน เขาไม่จำเป็นต้องอ่านคำถามส่วนตัวทุกข้อความ จึงสามารถเตรียมตัวอย่างการสอนสำหรับกลุ่มนี้ได้เร็วขึ้น

**Action sequence:** ครูเข้าสู่ระบบ → เปิด Dashboard → เลือกกลุ่มเรียน → กรองหัวข้อและช่วงเวลา → อ่านสรุปจำนวนการติดขัดและผลการฝึก → วางแผนสอนเสริม

**Problem/edge case:** หากกลุ่มเรียนยังไม่มีข้อมูล ระบบต้องแสดง empty state แทนตัวเลขศูนย์ที่ทำให้ตีความผิด

**Expected outcome:** ครูเห็นหัวข้อที่ควรช่วยเหลือและมีหลักฐานเพียงพอสำหรับจัดลำดับความสำคัญ

## S-05 — ครูตรวจความสดใหม่และสิทธิ์ข้อมูล

**Persona:** ครูสมชาย — Teacher Mentor  
**Objective:** ป้องกันการใช้ข้อมูลเก่าหรือข้อมูลของกลุ่มที่ครูไม่ได้รับผิดชอบ

**Narrative:** ครูสมชายเปิด Dashboard ในตอนเช้าและเห็น timestamp ว่าข้อมูลล่าสุดถูก sync เมื่อ 20 นาทีที่แล้ว เขาต้องการตรวจกลุ่มเรียนอื่นที่ไม่ได้อยู่ในความรับผิดชอบ แต่ระบบปฏิเสธคำขอและไม่เผยชื่อหรือผลการฝึกของนักเรียนกลุ่มนั้น เมื่อการ sync ครั้งถัดไปล้มเหลว Dashboard ยังคงแสดง timestamp ล่าสุดพร้อมป้ายแจ้งเตือนว่าไม่ใช่ข้อมูล real-time

**Action sequence:** ครูเปิด Dashboard → ตรวจ timestamp → ขอเปลี่ยนกลุ่มเรียน → ระบบตรวจสิทธิ์ → ปฏิเสธข้อมูลที่ไม่มีสิทธิ์ → แสดงสถานะ sync ล่าสุดเมื่อการอัปเดตล้มเหลว

**Problem/edge case:** ผู้ใช้ที่ไม่มีสิทธิ์ต้องไม่ได้รับข้อมูลแม้จะเดา URL หรือแก้ query parameter เอง

**Expected outcome:** ครูรู้ว่าข้อมูลใหม่แค่ไหนและเชื่อถือขอบเขตการเข้าถึงของระบบได้

## S-06 — ครูวางแผนสอนเสริมจากหลักฐาน

**Persona:** ครูสมชาย — Teacher Mentor  
**Objective:** ใช้ผลการฝึกเพื่อเลือกวิธีช่วยเหลือที่เหมาะสม

**Narrative:** หลังจากดูสรุป ครูสมชายพบว่านักเรียนส่วนใหญ่ทำโจทย์พื้นฐานได้ แต่ยังสับสนเมื่อโจทย์เปลี่ยนเงื่อนไข เขาเปิดรายละเอียดระดับหัวข้อที่ระบบอนุญาตให้ดูและเปรียบเทียบผลก่อนและหลังการฝึก ครูจึงวางกิจกรรมสั้น ๆ เรื่องการเลือกกฎอนุรักษ์ให้กับกลุ่มนี้ และไม่เสียเวลาสอนซ้ำในส่วนที่นักเรียนทำได้แล้ว

**Action sequence:** ครูเลือกหัวข้อ → ดูแนวโน้มผลการฝึก → แยกจุดที่ยังผิดซ้ำ → เลือกกิจกรรมช่วยเหลือ → บันทึกแผนสอนเสริมของตนเอง

**Problem/edge case:** ระบบต้องไม่สรุปว่า “เข้าใจแล้ว” จากคำตอบเพียงข้อเดียว หากยังไม่มีเกณฑ์ที่ทีมอนุมัติ

**Expected outcome:** แผนสอนเสริมเชื่อมโยงกับหลักฐานการฝึกและไม่เปิดเผยข้อมูลเกินความจำเป็น

## S-07 — จัดการงานและกำหนดส่ง

**Persona:** พี่เอิร์ธ — Adult Learner  
**Objective:** ช่วยให้ผู้เรียนเห็นงานที่ต้องทำ วันครบกำหนด และระดับความเร่งด่วนในที่เดียว

**Narrative:** พี่เอิร์ธมีเวลาว่างไม่แน่นอนและต้องจัดการงานเรียนหลายรายการ เขาเปิด Deadline Planner แล้วกรอกชื่องาน วิชา วันที่และเวลา deadline จากนั้นเลือกระดับความเร่งด่วนว่า “ด่วน”, “ปานกลาง” หรือ “ไม่ด่วน” เมื่อบันทึก ระบบแสดงรายการเรียงตามวันส่งพร้อมป้ายระดับความเร่งด่วน เขากรองดูเฉพาะงานที่ยังไม่เสร็จ ทำเครื่องหมายงานที่ส่งแล้ว และลบรายการที่ไม่ต้องใช้ต่อได้

**Action sequence:** พี่เอิร์ธกรอกงานและวิชา → ระบุวัน–เวลา deadline → เลือกระดับความเร่งด่วน → บันทึก → ตรวจรายการเรียงตามวันส่ง → กรองหรือเปลี่ยนสถานะงาน

**Problem/edge case:** หากยังไม่มีงานหรือไม่มีงานตรงกับตัวกรอง ระบบต้องแสดง empty state แทนการใส่รายการตัวอย่าง และถ้ากรอกข้อมูลสำคัญไม่ครบต้องแจ้งให้แก้ไขก่อนบันทึก

**Expected outcome:** พี่เอิร์ธเห็น deadline และงานด่วนอย่างชัดเจน จึงวางแผนลำดับการทำงานได้โดยไม่ต้องจำเอง

## S-08 — ผู้เรียนเปิด Progress โดยยังไม่มีประวัติ

**Persona:** พี่เอิร์ธ — Adult Learner  
**Objective:** แสดงความก้าวหน้าอย่างซื่อสัตย์เมื่อยังไม่มีข้อมูล

**Narrative:** พี่เอิร์ธสมัครใช้งานแต่ยังไม่เคยทำแบบฝึกหัด เขาเปิดหน้า Progress เพื่อดูว่าจะเริ่มจากตรงไหน ระบบไม่แสดงกราฟหลอกหรือคะแนนศูนย์ที่ตีความได้ว่าเขาสอบตก แต่แสดง empty state พร้อมคำแนะนำให้เลือกหัวข้อแรกและอธิบายว่าข้อมูลจะเริ่มบันทึกหลังส่งคำตอบ เขาจึงเริ่มบทเรียนสั้น ๆ และกลับมาดู Progress ได้ภายหลัง

**Action sequence:** พี่เอิร์ธเข้าสู่ระบบ → เปิดหน้า Progress → ระบบตรวจว่าไม่มีประวัติ → แสดง empty state → พี่เอิร์ธเลือกหัวข้อเริ่มต้น → ระบบสร้างผลลัพธ์หลังการฝึกครั้งแรก

**Problem/edge case:** ต้องแยก “ยังไม่มีข้อมูล” ออกจาก “ทำได้ศูนย์คะแนน” ให้ชัดเจน

**Expected outcome:** ผู้เรียนเข้าใจสถานะของตนเองและรู้ขั้นตอนถัดไปโดยไม่เข้าใจผิด

## S-09 — จัดเก็บและเปิดดูเอกสารการเรียน

**Persona:** พี่เอิร์ธ — Adult Learner  
**Objective:** ช่วยให้ผู้เรียนรวบรวมเอกสารการเรียนและเปิดกลับมาทบทวนได้ง่าย

**Narrative:** พี่เอิร์ธมีไฟล์การเรียนหลายประเภทกระจายอยู่ในเครื่อง เขาเปิด Document Library แล้วเลือกไฟล์ PDF หรือเอกสารที่ต้องการเพิ่ม ระบบให้เลือกหมวดวิชาและสร้างการ์ดที่แสดงชื่อไฟล์ ประเภท และหมวดวิชา เขาเลือกตัวกรองเพื่อดูเฉพาะวิชาที่กำลังเรียน กดการ์ดเพื่อเปิด Document Viewer และลบไฟล์ที่ไม่ต้องการออกจากรายการได้

**Action sequence:** พี่เอิร์ธเลือกไฟล์ → กำหนดหมวดวิชา → ระบบสร้างการ์ดเอกสาร → กรองตามวิชา → เปิดดูเอกสาร → ยืนยันการลบเมื่อไม่ต้องการ

**Problem/edge case:** หากยังไม่มีเอกสารหรือไม่มีเอกสารตรงกับตัวกรอง ระบบต้องแสดง empty state และ prototype ต้องไม่ทำให้ผู้ใช้เข้าใจว่าไฟล์ถูกเก็บถาวร เพราะข้อมูลจะอยู่ในหน่วยความจำของหน้าเว็บเท่านั้น

**Expected outcome:** พี่เอิร์ธเห็นเอกสารของตนเองเป็นหมวดหมู่ เปิดดูไฟล์ที่ต้องการได้เร็ว และจัดการรายการได้โดยไม่ต้องค้นจากโฟลเดอร์หลายแห่ง
