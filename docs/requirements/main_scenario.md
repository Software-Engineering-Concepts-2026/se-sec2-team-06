# Main Scenario — เรียนรู้จากจุดที่ยังไม่เข้าใจ

> SynapseSync ช่วยให้ผู้เรียนเปลี่ยนคำถามที่ติดขัดให้เป็นคำอธิบาย แบบฝึกหัด และข้อมูลความก้าวหน้าที่นำไปใช้ต่อได้

## Scenario Overview

| รายการ | รายละเอียด |
|---|---|
| **Primary Persona** | [ปันปัน — Student Learner](./personas/student_learner.md) |
| **Supporting Persona** | [ครูสมชาย — Teacher Mentor](./personas/teacher_mentor.md) |
| **Goal** | ทำความเข้าใจเรื่องโมเมนตัมและการชนก่อนสอบภายใน 3 วัน |
| **Trigger** | ปันปันทำโจทย์ท้ายบทไม่ได้และไม่เข้าใจเหตุผลเบื้องหลังคำตอบ |
| **Expected Outcome** | ปันปันเข้าใจแนวคิด ทำโจทย์ฝึกได้ และครูเห็นข้อมูลที่ช่วยวางแผนสอนเสริม |

## Narrative Scenario

### 1. Encountering the Problem

ปันปันกำลังทบทวนเรื่อง **โมเมนตัมและการชน** ก่อนสอบฟิสิกส์ในอีกสามวัน ระหว่างทำโจทย์ท้ายบท เธอติดอยู่ที่โจทย์การชนแบบไม่ยืดหยุ่นและไม่เข้าใจว่าเหตุใดพลังงานจลน์จึงไม่คงที่ ทั้งที่โมเมนตัมยังคงที่

ที่ผ่านมาเธอต้องค้นหาคลิปอธิบายหลายรายการกว่าจะพบเนื้อหาที่ตรงกับคำถาม แต่ครั้งนี้เธอเปิด SynapseSync และพิมพ์สิ่งที่สงสัยลงในผู้ช่วย AI โดยตรง

### 2. Identifying the Learning Gap

ระบบไม่รีบแสดงเฉลยทันที แต่ถามกลับเพื่อแยกให้ชัดว่าปันปันติดที่นิยาม สูตรคำนวณ หรือความแตกต่างระหว่างกฎอนุรักษ์ทั้งสองข้อ เมื่อได้บริบทเพียงพอ ระบบจึงอธิบายทีละขั้นด้วยภาษาที่เข้าใจง่ายและตัวอย่างใกล้ตัว

### 3. Practicing the Concept

หลังปันปันระบุว่าเข้าใจคำอธิบายแล้ว ระบบสร้างโจทย์ที่ใช้แนวคิดเดียวกันอีก 2 ข้อให้ฝึกทันที ปันปันส่งคำตอบและได้รับผลย้อนกลับสำหรับแต่ละข้อ เมื่อทำถูกทั้งสองข้อ ระบบบันทึกหลักฐานการฝึกและอัปเดตสถานะความเข้าใจของหัวข้อนี้

### 4. Supporting the Teacher

แดชบอร์ดของครูสมชายแสดงว่าปันปันเคยติดขัดเรื่องการชนแบบไม่ยืดหยุ่น แต่สามารถแก้โจทย์ฝึกที่เกี่ยวข้องได้แล้ว ครูจึงไม่จำเป็นต้องทบทวนหัวข้อนี้ซ้ำโดยไม่มีข้อมูลรองรับ และสามารถให้เวลากับนักเรียนที่ยังต้องการความช่วยเหลือได้มากขึ้น

## Happy Path

1. ผู้เรียนเข้าสู่ระบบและส่งคำถามเกี่ยวกับเนื้อหาที่ไม่เข้าใจ
2. ระบบขอข้อมูลเพิ่มเมื่อคำถามยังไม่ชัดเจน
3. ระบบอธิบายแนวคิดโดยไม่เปิดเผยเฉลยเพียงอย่างเดียว
4. ผู้เรียนยืนยันความเข้าใจและขอโจทย์ฝึกเพิ่มเติม
5. ระบบตรวจคำตอบ บันทึกผล และอัปเดตความก้าวหน้า
6. ผู้สอนที่มีสิทธิ์เห็นข้อมูลสรุปที่จำเป็นต่อการช่วยเหลือ

## Edge Cases to Validate

- คำถามว่าง สั้นเกินไป หรือไม่เกี่ยวข้องกับการเรียน
- ผู้เรียนยังไม่เข้าใจหลังได้รับคำอธิบายครั้งแรก
- AI provider ตอบช้า ไม่พร้อมใช้งาน หรือให้คำตอบที่ไม่มั่นใจ
- ผู้เรียนออกจากหน้าระหว่างทำโจทย์และกลับมาทำต่อภายหลัง
- ผู้สอนพยายามเปิดข้อมูลของผู้เรียนที่ไม่ได้อยู่ในความรับผิดชอบ
- ระบบไม่ควรสรุปว่า “เข้าใจแล้ว” จากคำตอบเพียงข้อเดียวโดยไม่มีเกณฑ์ที่ทีมอนุมัติ

## User Stories and Acceptance Criteria

> **หมายเหตุ:** Priority และ Estimate เป็น product decision ของทีม จึงระบุเป็น `Team confirmation required` จนกว่าจะผ่าน Sprint Planning

### US-01 — Ask for Help

**As a** นักเรียน, **I want** ถามคำถามเกี่ยวกับโจทย์ที่ไม่เข้าใจกับ AI ผู้ช่วยได้ทันที, **so that** ฉันไม่ต้องรอครูหรือเสียเวลาหาคลิปที่ตรงประเด็น

**Acceptance Criteria**

- **Given** นักเรียนเข้าสู่ระบบแล้ว **When** ส่งคำถามที่มีข้อความ **Then** ระบบรับคำถามและแสดงสถานะว่ากำลังประมวลผล
- **Given** ช่องคำถามว่าง **When** นักเรียนกดส่ง **Then** ระบบไม่ส่งคำขอและแจ้งให้กรอกคำถาม
- **Given** บริการ AI ไม่พร้อม **When** นักเรียนส่งคำถาม **Then** ระบบแจ้งปัญหาโดยไม่ทำให้ข้อความที่พิมพ์สูญหาย

**INVEST note:** Valuable และ Testable แต่ยัง Large หากรวมการตีความและการอธิบายทั้งหมด
**Priority / Estimate:** Team confirmation required

### US-02 — Clarify the Learning Gap

**As a** นักเรียน, **I want** ให้ AI ถามกลับเพื่อระบุจุดที่ฉันไม่เข้าใจก่อนอธิบาย, **so that** คำอธิบายตรงกับปัญหาจริงของฉัน

**Acceptance Criteria**

- **Given** คำถามมีความกำกวม **When** ระบบมีข้อมูลไม่พอ **Then** ระบบถามคำถามชี้แจงอย่างน้อย 1 ข้อก่อนอธิบาย
- **Given** นักเรียนตอบคำถามชี้แจงแล้ว **When** ระบบสร้างคำอธิบาย **Then** คำอธิบายต้องอ้างอิงบริบทที่นักเรียนเพิ่มเข้ามา

**INVEST note:** Valuable สูง แต่ต้อง prototype เพื่อประเมิน AI logic
**Priority / Estimate:** Team confirmation required

### US-03 — Generate Related Practice

**As a** นักเรียน, **I want** ได้รับโจทย์ฝึกที่คล้ายกับข้อที่เพิ่งเข้าใจ, **so that** ฉันตรวจสอบได้ว่าเข้าใจแนวคิดจริงก่อนสอบ

**Acceptance Criteria**

- **Given** นักเรียนเปิดหัวข้อที่เพิ่งศึกษา **When** ขอแบบฝึกหัด 2 ข้อ **Then** ระบบแสดงโจทย์ 2 ข้อที่สัมพันธ์กับหัวข้อนั้น
- **Given** นักเรียนส่งคำตอบ **When** ระบบตรวจผล **Then** ระบบแสดงผลถูก/ผิดและคำอธิบายที่เกี่ยวข้อง

**INVEST note:** Small และ Testable เหมาะสำหรับ MVP
**Priority / Estimate:** Team confirmation required

### US-04 — Record Understanding

**As a** นักเรียน, **I want** ให้ระบบบันทึกหัวข้อที่ฉันฝึกและผลที่ทำได้, **so that** ฉันติดตามความเข้าใจโดยไม่ต้องจดจำเอง

**Acceptance Criteria**

- **Given** นักเรียนส่งคำตอบแบบฝึกหัดแล้ว **When** ระบบตรวจผลเสร็จ **Then** ระบบบันทึกหัวข้อ เวลา และผลการฝึก
- **Given** นักเรียนกลับมาเปิดประวัติ **When** เลือกหัวข้อเดิม **Then** ระบบแสดงผลการฝึกครั้งล่าสุดได้ถูกต้อง

**INVEST note:** Small, Testable และค่อนข้าง Independent
**Priority / Estimate:** Team confirmation required

### US-05 — View Learning Gaps

**As a** ผู้สอน, **I want** เห็นภาพรวมว่านักเรียนคนใดติดขัดเรื่องอะไรและมีหลักฐานการฝึกหรือไม่, **so that** ฉันจัดสรรเวลาสอนเสริมได้ตรงจุด

**Acceptance Criteria**

- **Given** ผู้สอนมีสิทธิ์ดูแลกลุ่มเรียน **When** เปิด dashboard **Then** ระบบแสดงหัวข้อที่มีการติดขัดและสถานะการฝึกของนักเรียนในกลุ่มนั้น
- **Given** ผู้สอนไม่มีสิทธิ์ในกลุ่มเรียน **When** ขอเปิดข้อมูล **Then** ระบบปฏิเสธการเข้าถึง

**INVEST note:** Valuable แต่ Large ควรแยกมุมมองรายหัวข้อและรายนักเรียนเมื่อนำเข้า backlog
**Priority / Estimate:** Team confirmation required

### US-06 — See Current Information

**As a** ผู้สอน, **I want** เห็นเวลาที่ข้อมูลความเข้าใจของนักเรียนอัปเดตล่าสุด, **so that** ฉันรู้ว่าข้อมูลที่ใช้ตัดสินใจใหม่เพียงใด

**Acceptance Criteria**

- **Given** นักเรียนส่งผลการฝึกสำเร็จ **When** ผู้สอนเปิดหรือ refresh dashboard **Then** ระบบแสดงข้อมูลล่าสุดพร้อม timestamp
- **Given** การอัปเดตล้มเหลว **When** ผู้สอนดูข้อมูล **Then** ระบบแสดงเวลาที่ sync สำเร็จครั้งล่าสุดแทนการอ้างว่าเป็น real-time

**INVEST note:** Testable ผ่าน timestamp แต่ต้องกำหนดเกณฑ์ความสดของข้อมูล
**Priority / Estimate:** Team confirmation required

### US-07 — Receive Review Reminders

**As a** ผู้เรียนผู้ใหญ่, **I want** ได้รับการเตือนให้กลับมาทบทวนเนื้อหา, **so that** ฉันเรียนต่อเนื่องได้แม้ตารางงานไม่แน่นอน

**Acceptance Criteria**

- **Given** ผู้เรียนเปิดการแจ้งเตือนและกำหนดเวลาไว้ **When** ถึงเวลาที่กำหนด **Then** ระบบสร้างการแจ้งเตือนทบทวนหัวข้อที่เกี่ยวข้อง
- **Given** ผู้เรียนปิดการแจ้งเตือน **When** ถึงกำหนดเดิม **Then** ระบบไม่ส่งการแจ้งเตือน

**INVEST note:** Valuable, Small และ Testable
**Priority / Estimate:** Team confirmation required

### US-08 — Track Personal Progress

**As a** ผู้เรียนผู้ใหญ่, **I want** เห็นความก้าวหน้าการเรียนของตัวเองเป็นสรุปที่เข้าใจง่าย, **so that** ฉันมีแรงจูงใจและรู้ว่าควรทบทวนหัวข้อใดต่อ

**Acceptance Criteria**

- **Given** ผู้เรียนมีประวัติการฝึก **When** เปิดหน้าความก้าวหน้า **Then** ระบบแสดงจำนวนหัวข้อที่ฝึก ผลล่าสุด และช่วงเวลาของข้อมูล
- **Given** ยังไม่มีข้อมูล **When** เปิดหน้าความก้าวหน้า **Then** ระบบแสดง empty state พร้อมคำแนะนำเริ่มต้น

**INVEST note:** Valuable และ Negotiable ในรูปแบบการแสดงผล
**Priority / Estimate:** Team confirmation required

### US-09 — Receive a Learning Summary

**As a** ผู้ปกครองที่ได้รับ consent, **I want** ได้รับข้อมูลสรุปการเรียนที่จำเป็น, **so that** ฉันช่วยเหลือผู้เรียนได้โดยไม่ต้องติดตามหรือกดดันตลอดเวลา

**Acceptance Criteria**

- **Given** ผู้เรียนให้ consent ที่ยังมีผล **When** ระบบสร้างสรุป **Then** ผู้ปกครองเห็นเฉพาะข้อมูลที่อยู่ในขอบเขต consent
- **Given** ไม่มี consent หรือ consent ถูกถอน **When** ผู้ปกครองขอข้อมูล **Then** ระบบปฏิเสธการเข้าถึงและไม่เปิดเผยข้อมูลการเรียน

**INVEST note:** ต้องออกแบบ privacy และ permission ก่อนนำเข้าสู่ MVP
**Priority / Estimate:** Team confirmation required

### US-10 — Receive an Early Warning

**As a** ผู้ปกครองที่ได้รับ consent, **I want** ได้รับการแจ้งเตือนเมื่อผู้เรียนมีปัญหากับหัวข้อเดิมต่อเนื่อง, **so that** ฉันช่วยหาแนวทางสนับสนุนได้ทันเวลา

**Acceptance Criteria**

- **Given** ทีมกำหนด threshold และมี consent แล้ว **When** ผลการฝึกถึง threshold **Then** ระบบสร้างการแจ้งเตือนพร้อมหัวข้อและช่วงเวลาที่เกี่ยวข้อง
- **Given** ผลการฝึกยังไม่ถึง threshold **When** ระบบประเมินข้อมูล **Then** ระบบไม่ส่งการแจ้งเตือน

**INVEST note:** Valuable แต่ Large; threshold และช่องทางแจ้งเตือนควรแยกเป็นงานย่อย
**Priority / Estimate:** Team confirmation required
