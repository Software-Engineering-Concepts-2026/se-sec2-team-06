# WebApp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** สร้าง WebApp ใหม่ที่ root ของ `se-sec2-team-06-main-new` ซึ่ง build และรันด้วย Docker ได้ มี API boundary ไปยัง FastAPI และไม่แก้ไฟล์ใต้ `prototypes/`.

**Architecture:** ใช้ Vite + Vanilla JavaScript เป็น frontend build, Nginx เป็น production static server และ FastAPI เดิมเป็น backend ผ่าน same-origin `/api`. WebApp จะรู้จักเฉพาะ API client ของตัวเองและจะแสดงสถานะเชื่อมต่อ/ข้อผิดพลาดโดยไม่ฝัง AI key หรือข้อมูลจำลองที่ทำให้ดูเหมือนระบบจริง.

**Tech Stack:** Node.js 24 (local runtime ที่ตรวจพบ), Vite, Vitest, Vanilla JavaScript, Nginx Alpine, FastAPI/Python 3.12, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-09-22-webapp-design.md`

## Global Constraints

- สร้างไฟล์ application ใหม่เฉพาะใต้ `WebApp/` และไฟล์ Compose ที่ root เท่าที่จำเป็น
- ห้ามแก้ ย้าย ลบ หรือ import runtime จาก `prototypes/`
- ห้ามใส่ `AI_API_KEY`, `DATABASE_URL`, password หรือ provider secret ใน frontend, Docker build args หรือ Git
- ใช้ `/api` เป็น base path เดียวของ browser client
- WebApp รอบแรกเป็น shell + API health boundary; ห้ามอ้างว่า AI generation หรือ database เสร็จถ้ายังไม่มี backend endpoint
- คง FastAPI Modular Monolith ใน `services/api/`; ไม่สร้าง microservice ใหม่

## Review Focus

- FastAPI ยังต้องตอบ `/health` แบบเดิม และต้องเพิ่ม `/api/health` โดย response ต้องเท่ากัน — ทดสอบใน `services/api/tests/test_health.py`
- API ปิดหรือคืน non-2xx ต้องเปลี่ยนสถานะ WebApp เป็นข้อความที่อ่านได้และไม่แสดง stack trace — ทดสอบใน `WebApp/tests/api-client.test.js`
- API คืน JSON ผิด schema ต้องถูกปฏิเสธอย่างชัดเจน ไม่ถูกนำไป render เป็น quiz — ทดสอบใน `WebApp/tests/api-client.test.js`
- production image ต้อง build ได้โดยไม่มี `.env` และไม่คัดลอก `prototypes/` เข้า image — ตรวจด้วย Docker build และ `.dockerignore`
- direct navigation ของ static route ต้องไม่เป็น 404 — ตรวจด้วย Nginx `try_files` และ smoke test หลัง container start

### Task 2: Add the FastAPI health contract and tested API client

**Files:**
- Create: `WebApp/src/api/client.js`

- Modify: `WebApp/src/main.js`

**Interfaces:**
- `getApiHealth({ fetchImpl, basePath }) -> Promise<{ status: string, service: string, architecture: string, version: string }>`
- `ApiError` has `status` and a safe user-facing `message`.
- FastAPI exposes both `/health` (legacy contract) and `/api/health` (WebApp contract) with the same JSON response.

- [ ] **Step 1: Write failing API-client tests**

Create `WebApp/tests/api-client.test.js` with Vitest tests for a successful response, a non-2xx response, and malformed JSON. The success case must use a fake `fetchImpl` and assert that the requested URL is `/api/health`:

~~~js
import { describe, expect, it, vi } from 'vitest';
import { ApiError, getApiHealth } from '../src/api/client.js';

describe('getApiHealth', () => {
  it('requests the same-origin health endpoint and returns the contract', async () => {
    const fetchImpl = vi.fn().mockResolvedValue({
      ok: true,
      status: 200,
      json: async () => ({
        status: 'healthy',
        service: 'synapsesync-api',
        architecture: 'modular-monolith',
        version: '0.1.0'
      })
    });

    await expect(getApiHealth({ fetchImpl })).resolves.toEqual({
      status: 'healthy',
      service: 'synapsesync-api',
      architecture: 'modular-monolith',
      version: '0.1.0'
    });
    expect(fetchImpl).toHaveBeenCalledWith('/api/health', { headers: { Accept: 'application/json' } });
  });

  it('turns a failed response into a safe ApiError', async () => {
    const fetchImpl = vi.fn().mockResolvedValue({ ok: false, status: 503, json: async () => ({}) });
    await expect(getApiHealth({ fetchImpl })).rejects.toMatchObject({ status: 503 });
    await expect(getApiHealth({ fetchImpl })).rejects.toBeInstanceOf(ApiError);
  });

  it('rejects a response that does not match the health contract', async () => {
    const fetchImpl = vi.fn().mockResolvedValue({ ok: true, status: 200, json: async () => ({ status: 'healthy' }) });
    await expect(getApiHealth({ fetchImpl })).rejects.toThrow('Invalid API health response');
  });
});
~~~

### Task 3: Package WebApp and API together with Docker

**Files:**
- Create: `WebApp/Dockerfile`
- Create: `WebApp/nginx.conf`
- Create: `WebApp/.dockerignore`
- Create: `compose.webapp.yml`

**Interfaces:**
- WebApp image listens on port 80.
- Compose publishes WebApp at `http://127.0.0.1:8080` and API at `http://127.0.0.1:8000`.
- Nginx proxies `/api/health` to the `api` service without exposing secrets.

- [ ] **Step 1: Create the WebApp production Dockerfile**

Create `WebApp/Dockerfile`:

~~~dockerfile
FROM node:24-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . ./
RUN npm run build

FROM nginx:alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
HEALTHCHECK --interval=30s --timeout=3s --retries=3 CMD wget --spider --quiet http://127.0.0.1/ || exit 1
~~~

- [ ] **Step 2: Configure Nginx routing**

Create `WebApp/nginx.conf` so `/` and direct frontend routes use `try_files $uri $uri/ /index.html`, while `/api/` uses `proxy_pass http://api:8000;` and forwards `Host`, `X-Real-IP`, and `X-Forwarded-For` headers. Do not put an AI key or database URL in this file.

- [ ] **Step 3: Exclude development files from the image context**

Create `WebApp/.dockerignore` excluding `.env*`, `node_modules`, `dist`, `tests`, `.git`, and editor files. Confirm it does not exclude `src`, `public`, `index.html`, `package*.json`, `nginx.conf`, or `Dockerfile`.

- [ ] **Step 4: Create the root Compose file**

Create `compose.webapp.yml` with:

~~~yaml
services:
  api:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "8000:8000"
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health', timeout=2)"]
      interval: 10s
      timeout: 3s
      retries: 5

  webapp:
    build: ./WebApp
    ports:
      - "8080:80"
    depends_on:
      api:
        condition: service_healthy
~~~

This first Compose file does not add PostgreSQL or an AI provider because their endpoints and migrations are not part of the approved WebApp scaffold. They can be added in a later plan without changing `prototypes/`.

- [ ] **Step 5: Build and smoke-test the images**

Run from the repository root:

~~~powershell
docker compose -f compose.webapp.yml build
docker compose -f compose.webapp.yml up -d
docker compose -f compose.webapp.yml ps
Invoke-WebRequest http://127.0.0.1:8080/ -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:8080/api/health -UseBasicParsing
docker compose -f compose.webapp.yml down
~~~

Expected: both services are healthy, the WebApp HTML is returned, `/api/health` returns the FastAPI JSON contract, and `down` removes only the test containers/network.

- [ ] **Step 6: Commit Docker packaging**

~~~powershell

git commit -m "build: package WebApp with FastAPI"
~~~
