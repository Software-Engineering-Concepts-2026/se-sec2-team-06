"จากแนวคิด 'Software Entropy' และ 'Broken Window Theory' ลองมองย้อนกลับไปในโปรเจกต์ที่คุณเคยทำ มี 'หน้าต่างที่แตก' บานไหนที่คุณเคยปล่อยปละละเลย และมันส่งผลกระทบอย่างไรในระยะยาว?"

** เคยมีการใช้Aiช่วยในการแก้ปัญหาแต่ไม่ใช้ต่อเนื่องทำให้โค้ดบางตัวเชื่อมต่อกันอย่างผิดและบางตัวก็ไม่รู้ว่าAiนั้นให้อะไรมา**

 *ผลระยะยาวที่กระทบ* 
ทำให้เกิดปัญหาใหญ่ขึ้นเมื่อต้องการดึงข้อมูลจากอีกหน้าไปใช้อีกหน้าไม่ได้และต้องมาไล่โค้ดใหม่ทั้งหมดทำให้เสียเวลาในการทำงานเป็นอย่างมากและอันที่ไม่รู้ว่าให้มาทำไมก็ทำให้การทำงานเราสับสนเวลาทำงานอีกด้วยครับ


###
"อธิบายหลักการ 'Take Responsibility' ในความเข้าใจของคุณ และยกตัวอย่างสถานการณ์ที่คุณจะนำหลักการ 'Provide Options, Don't Make Lame Excuses' ไปใช้ในการสื่อสารกับเพื่อนร่วมทีมในโปรเจกต์นี้"

*อธิบายหลักการ 'Take Responsibility'*
การพัฒนาตนเองและยอมรับผลที่เกิดขึ้นจากการกระทำไม่ว่าจะถูกหรือผิดและไม่โทษคนอื่นไปทั่วให้ลองคิดว่าเราผิดไหมก่อน

*ยกตัวอย่างสถานการณ์ที่คุณจะนำหลักการ 'Provide Options, Don't Make Lame Excuses'*
สมมุติว่า เมื่อเกิดการแก้ไขโค้ดผิดโดยจากที่ต้องแก้ใน branch ตัวเอง แต่กลับไปแก้ใน branch mainหรือแก้ใน branch หลักเลยและ Push ขึ้น git ด้วยไม่ได้เช็ค 
1.ก่อนอื่นต้องมาดูกันก่อนว่าในเครื่องเพื่อนในที่มมีโค้ดเดิมอยู่ไหม(ทุกคนควรมีเซฟในเครื่องตัวเองตลอด)
2.ควรเช็คว่าแก้ถูก branch ไหม(ของตัวเอง)
3.ถ้าเกิดเหตุเลวร้ายที่ไม่สามารถแก้ไขได้จริงๆ ทุกคนควรหาทางออก,เสนอข้อคิดเห็นและรีบลงมือทำให้งานสำเร็จไปตามเป้าหมายได้
