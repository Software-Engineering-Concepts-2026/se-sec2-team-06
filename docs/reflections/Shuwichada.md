1. "จากแนวคิด 'Software Entropy' และ 'Broken Window Theory' ลองมองย้อนกลับไปในโปรเจกต์ที่คุณเคยทำ มี 'หน้าต่างที่แตก' บานไหนที่คุณเคยปล่อยปละละเลย และมันส่งผลกระทบอย่างไรในระยะยาว?"
ตอบ 
หน้าต่างที่แตก (ปัญหาที่ปล่อยปละละเลย) การปล่อยให้มี Duplicate Code (โค้ดซ้ำซ้อน) และไม่ยอมเขียนเอกสาร/คอมเมนต์กำกับโค้ดในช่วงที่เร่งรีบส่งงาน โดยคิดว่า "เดี๋ยวค่อยกลับมาแก้" ผลกระทบระยะยาว เกิด Technical Debt (หนี้ทางเทคนิค) โค้ดซับซ้อนจนไม่มีใครกล้าแก้ไขเพราะกลัวระบบพัง

2. "อธิบายหลักการ 'Take Responsibility' ในความเข้าใจของคุณ และยกตัวอย่างสถานการณ์ที่คุณจะนำหลักการ 'Provide Options, Don't Make Lame Excuses' ไปใช้ในการสื่อสารกับเพื่อนร่วมทีมในโปรเจกต์นี้"
ตอบ
หลักการ"TakeResponsibility"คือการยืดอกรับผิดชอบต่อผลลัพธ์ของ
งานตัวเอง ไม่โทรกระทบสิ่งแวดล้อม เครื่องมือ หรือเพื่อนร่วมทีมแต่
โฟกัสที่การแก้ปัญหาในส่วนที่เราควบคุมได้
